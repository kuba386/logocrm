# Карта проекта

Где что лежит — чтобы не искать `find`/`grep` заново в начале задачи.
Актуализировать при структурных изменениях (новый пакет, новая корневая
папка); за списком отдельных файлов не гнаться — это не индекс, а карта.

## apps/web — Next.js 15 App Router

- `app/app/` — экраны за авторизацией, ветвление по роли внутри страниц, не отдельными путями («одна страница на все роли», CLAUDE.md).
  - `page.tsx`, `layout.tsx` — вход в `/app`, роль читается из БД (не JWT)
  - `dashboard-admin.tsx` / `dashboard-parent.tsx` / `dashboard-teacher.tsx` — три версии `/app`, выбор в `page.tsx`
  - `schedule/` — расписание: `week-grid.tsx` (сетка), `lesson-panel.tsx` (диалог занятия — статус/отмена/перенос/замена + переключение в `attendance-panel.tsx`), `create-dialog.tsx` (создание серии), `actions.ts`
  - `students/` — список (`students-table.tsx`) + карточка `[id]/page.tsx` (данные, плательщик, `subscriptions-panel.tsx` с вкладками «Абонементы»/«Посещения»)
  - `settings/` — `attendance-statuses/`, `subscription-types/`, `services`/`rooms` (в `services/`), `staff/` — CRUD-справочники, общий `CatalogForm`/`CatalogAction`; `plan/` — тариф, лимиты и заявка на оплату из `center_limits()` (этап 8a), баннер срока — `plan-banner.tsx`, разбор ответа — `lib/plan.ts`
- `app/admin/` — пульт платформы (`is_platform_admin()`, отдельный layout без выбора центра): открытые заявки из `platform_open_payments()`, подтверждение `extend_subscription`, отклонение, выручка по `platform_payments`
  - `debts/` — список должников
  - `payers/`, `groups/` — плательщики, группы
  - `telegram/` — своя привязка чата, страница для всех ролей (родителю нужнее всего, а настройки центра он не видит)
  - `notifications/` — журнал отправок (owner/admin); тексты сообщений — в `settings/notifications/`
- `app/{auth,login,onboarding,select-center,invite,access-revoked,error}/` — до входа в `/app` или вне текущего центра
- `components/ui/` — общие примитивы: `button`, `card`, `dialog`, `catalog-form.tsx` (форма справочника), `catalog-action.tsx` (кнопка-действие: архив/восстановить/default)
- `lib/` — `errors.ts` (**единственное** место разбора ошибок Postgres → русский текст), `attendance.ts` (цвета/лейблы статусов), `timezone.ts` (рендер в поясе центра), `roles.ts`, `access.ts`, `schedule.ts`
- `e2e/` — Playwright: `fixtures.ts` (данные из `e2e.sql`), `helpers.ts` (общие хелперы: `openWeek`/`openTodayWeek`, `actAndAwait`, `studentCards`), `*.spec.ts` по темам, `auth.setup.ts`. Конфиг проектов (admin/teacher/parent, зависимости между ними) — `playwright.config.ts`

## apps/tg-bot — вебхук Telegram

Отдельный деплой (Railway / Fly / VPS), без зависимостей: `node:http` плюс
`fetch`. Команд три и одна кнопка — библиотека бота не окупается.

- `src/index.ts` — HTTP-сервер вебхука: проверка `secret_token`, мгновенный
  ответ Telegram, обработка в фоне (повторы безопасны — гашение кода
  атомарно, подтверждение идемпотентно)
- `src/commands.ts` — `/start <код>`, `/today`, `/balance`, подтверждение прихода
- `src/supabase.ts` — вызов RPC через PostgREST ключом роли `bot_worker`
- Рассылку бот **не делает**: сообщения шлёт n8n, забирая события из очереди

## packages/db — схема и миграции

- `supabase/migrations/000N_*.sql` — **неизменяемые после мержа**, пронумерованы по порядку; следующий номер = последний + 1
- `supabase/tests/000N_*.test.sql` — pgTAP, по одному файлу на миграцию (примерно), плюс `0007_function_grants.test.sql` (белый список того, что может исполнять `authenticated`) и `rls_smoke.test.sql`
- `supabase/fixtures/e2e.sql` — данные для Playwright (отдельно от `seed.sql`, который специально оставляет центр несозданным)
- `src/database.types.ts` — сгенерированные типы; теперь коммитит бот в CI при расхождении с миграциями (см. `.github/workflows/ci.yml`, джоб `db`)

## packages/core, packages/contracts

- `core/src/` — зеркало бизнес-логики на TS (money, subscription, schedule, age, phone) с тестами — там, где логика дублируется SQL↔TS, SQL источник истины, core — мгновенная подсказка
- `contracts/src/` — общие DTO и типы событий (`events.ts`, `dto.ts`)

## CI/CD и инструменты

- `.github/workflows/ci.yml` — джобы `app` (lint/typecheck/vitest), `db` (миграции с нуля + pgTAP + автокоммит типов), `e2e` (Playwright, только если тронуты `apps/web`/`packages`), `schema` (деплой, только push в main)
- `.github/workflows/deploy-staging.yml` — применение миграций в облачный Supabase
- `.claude/hooks/` — `no-build-while-dev.mjs` (блокирует `pnpm build` при живом dev), `applied-migration-guard.mjs` (блокирует правку уже смерджённой миграции)
- `.claude/agents/architect.md` — ревьюер схемы, обязателен до и после написания миграции
