# ADR-009. Что из клиники ребёнка покидает периметр ради ИИ

Дата: 2026-09-22. Статус: принято.

## Контекст

С этапа 7b голосовое резюме занятия проходит через внешнего провайдера
(OpenAI: распознавание речи и модель резюме) и через n8n на Railway.
ADR-005 описывает приватность колонок **внутри** продукта; про то, что
уходит третьей стороне, решения не было, и каждый следующий шаг (0048 —
список целей в промпт, этап 8 — квоты) выводил бы его заново.

## Решение

Наружу уходит ровно то, без чего задача не решается, и ничего, что
называет ребёнка **как поле**:

- **транскрипт** диктовки специалиста — по определению задачи;
- **активные цели ребёнка** (0048): `goal_id`, `title`, `area`, `sound`,
  `stage_title`. Без `target_date`, без оценок, без `note` из
  `goal_progress` (внутренняя пометка специалиста, 0046), без
  `custom_fields`;
- **не уходят** имя ребёнка, плательщик, диагностика, `soap` и
  `raw_transcript` прошлых заметок (на групповом занятии там имена
  соседей). Если прошлые заметки понадобятся модели — только
  `parent_summary` утверждённых заметок этого ребёнка, с обрезкой.

Свободный текст (транскрипт, `title` цели) под контролем схемы не
находится: специалист может назвать ребёнка голосом или в формулировке
цели. Это принятый остаточный риск; закрывается подсказкой на экране, не
констрейнтом.

Состав полей списка целей зафиксирован pgTAP (0048): добавление поля —
осознанное изменение этого ADR, а не побочный эффект `select *`.

## Следствия

- Аудио не хранится (0042); `file_id` вычищается из события после
  обработки; копия остаётся у Telegram.
- Данные выполнений воркфлоу `poll` в n8n не сохраняются — иначе
  транскрипт и формулировки целей оседают в БД n8n (n8n/README.md).
- Провайдер один — OpenAI (решение 20.09.2026); смена провайдера — правка
  в n8n, база его не знает (`ai_usage.model` — текст).
- Квота ИИ-заметок (этап 8) считается по `ai_usage`, а не по объёму
  переданных данных.

## Дополнение 24.09.2026: ассистент администратора (0064)

Второй контур с провайдером — синхронный вызов из веба (`OPENAI_API_KEY`
в Vercel, не n8n). Решение владельца: наружу уходит **только текст вопроса
и сегодняшняя дата в поясе центра**. Модель разбирает вопрос в намерение с
параметрами (function calling) и ничего больше не делает; ответ собирает
база под правами спросившего и рисует интерфейс. Имена детей, плательщики,
деньги, идентификаторы провайдеру не отправляются — тело запроса собирает
`buildClassifyRequest` (`@logocrm/contracts`), и Vitest держит его состав.

Один вопрос — ровно один вызов провайдера; второй вызов «сформулировать
ответ по данным» отправил бы наружу имена и суммы — это отдельное решение
владельца и правка этого ADR, не побочный шаг оптимизации.

Остаточный риск тот же, что с транскриптом: сотрудник может написать
фамилию или телефон в вопросе. Закрывается подсказкой на экране, не
констрейнтом. Текст вопроса в базе не хранится (`assistant_requests` —
актор, намерение, статус), расход — `ai_usage.kind = 'question'`.
