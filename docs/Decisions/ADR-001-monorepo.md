# ADR-001. Монорепозиторий на pnpm

Дата: 2026-09-07
Статус: принято

## Контекст

LogoCRM состоит из веб-приложения, схемы БД, бизнес-логики и контрактов событий.
Логика вычисления цены занятия нужна и в UI (показать родителю), и на сервере
(списать с абонемента), и в будущем воркере (начислить зарплату логопеду).
Схема БД и типы TypeScript обязаны меняться одной атомарной правкой — иначе
через неделю типы врут.

Альтернативы: несколько репозиториев с публикацией npm-пакетов; один
Next.js-проект без пакетов вовсе.

## Решение

Один репозиторий, pnpm workspaces, без Turborepo/Nx на старте.

```
apps/web            деплой
packages/db         SQL + сгенерированные типы
packages/core       бизнес-логика без внешних зависимостей
packages/contracts  zod-схемы
```

Внутренние пакеты не собираются в `dist`: они экспортируют TypeScript-исходники,
Next.js компилирует их через `transpilePackages`. Никакого шага сборки библиотек,
никаких stale-артефактов.

## Последствия

Хорошо:

- изменение схемы, типов и вызывающего кода — один PR и один прогон CI;
- `packages/core` тестируется в миллисекундах: ни базы, ни моков;
- граница «чистая логика ↔ инфраструктура» проведена физически, её нельзя
  случайно нарушить импортом.

Плохо:

- `packages/core` нельзя переиспользовать вне монорепы без публикации;
- CI прогоняет всё на каждом PR. При росте времени прогона добавим Turborepo
  с кэшем — но не раньше, чем это станет мешать.

Правило зависимостей: `core` не импортирует ничего; `contracts` — только `zod`;
`db` — только типы; `apps/web` — всё перечисленное. Обратные импорты запрещены.
