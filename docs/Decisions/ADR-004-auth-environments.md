# ADR-004. Подтверждение email: выключено на staging, обязательно на prod

Дата: 2026-09-07
Статус: принято

## Контекст

GoTrue по умолчанию требует подтверждения email: после регистрации сессия не
выдаётся, пока человек не перейдёт по ссылке из письма.

На staging это мешает и ничего не защищает. Тестовые адреса вроде
`aigul@test.kg` не существуют, письмо уходит в никуда, и любой сквозной прогон
сценария с приглашением упирается в недоступный почтовый ящик. Именно на этом
застрял первый ручной прогон этапа 1.

## Решение

- **staging** (`logocrm`, ref `hiwstqrnxrlfuanvfggq`): Confirm email **выключен**.
  Регистрация сразу выдаёт сессию.
- **prod** (создаётся на этапе 8): Confirm email **включён**. Отдельный проект,
  отдельная база, без seed-данных и без тестовых пользователей.
- **локальный стек**: `enable_confirmations = false` в
  `packages/db/supabase/config.toml` — совпадает со staging.

## Последствия

- Сценарии с приглашениями проходятся сквозняком в staging и локально без
  почтового ящика.
- Настройка живёт **не в репозитории**: `config.toml` управляет только локальным
  стеком, облачные проекты настраиваются в дашборде. Значит расхождение между
  средами не поймает ни CI, ни code review — это ручной пункт чеклиста при
  заведении prod на этапе 8.
- На prod регистрация без подтверждения недопустима: это доступ к персональным
  данным детей, и подтверждение адреса — минимальная проверка того, что человек
  владеет ящиком, на который придёт восстановление пароля.
- Тестовые пользователи (`owner@logocrm.kg` и подобные) существуют только в
  staging. На prod их не заводим — там и seed.sql не применяется.
