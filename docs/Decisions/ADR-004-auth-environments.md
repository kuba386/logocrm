# ADR-004. Подтверждение email: выключено на staging, обязательно на prod

Дата: 2026-09-07
Статус: принято

## Контекст

GoTrue по умолчанию требует подтверждения email: после регистрации сессия не
выдаётся, пока человек не перейдёт по ссылке из письма.

На staging это мешает и ничего не защищает. Тестовые адреса вроде
`aigul@test.kg` не существуют, письмо уходит в никуда, и любой сквозной прогон
сценария с приглашением упирается в недоступный почтовый ящик. Именно на этом
застрял первый ручной прогон этапа 1.

## Решение

- **staging** (`logocrm`, ref `hiwstqrnxrlfuanvfggq`): Confirm email **выключен**.
  Регистрация сразу выдаёт сессию.
- **prod** (создаётся на этапе 8): Confirm email **включён**. Отдельный проект,
  отдельная база, без seed-данных и без тестовых пользователей.
- **локальный стек**: `enable_confirmations = false` в
  `packages/db/supabase/config.toml` — совпадает со staging.

## Последствия

- Сценарии с приглашениями проходятся сквозняком в staging и локально без
  почтового ящика.
- Настройка живёт **не в репозитории**: `config.toml` управляет только локальным
  стеком, облачные проекты настраиваются в дашборде. Значит расхождение между
  средами не поймает ни CI, ни code review — это ручной пункт чеклиста при
  заведении prod на этапе 8.
- На prod регистрация без подтверждения недопустима: это доступ к персональным
  данным детей, и подтверждение адреса — минимальная проверка того, что человек
  владеет ящиком, на который придёт восстановление пароля.
- Тестовые пользователи (`owner@logocrm.kg` и подобные) существуют только в
  staging. На prod их не заводим — там и seed.sql не применяется.

## Дополнение 28.09.2026: капча на prod

- **prod**: Authentication → Attack Protection → **CAPTCHA protection ON**,
  провайдер Cloudflare Turnstile. Без токена Supabase отвечает 400
  `captcha_failed` на регистрацию, вход по паролю, ссылку на почту и
  восстановление пароля — то есть включать её можно только вместе с виджетом
  в формах.
- Виджет — `apps/web/components/turnstile-field.tsx`, включается ключом
  сайта `NEXT_PUBLIC_TURNSTILE_SITE_KEY` (Vercel, только `logocrm-prod`).
  Ключ не задан — виджета нет, формы работают как раньше: **staging и
  локальный стек капчи не имеют** (как и подтверждения email выше).
- Ключ сайта не секрет; **секрет Turnstile** вводится только в Supabase
  (Attack Protection) и в репозиторий не попадает.
- Расхождение окружений, как и с подтверждением email, живёт в дашборде, а
  не в репозитории: CI его не поймает. Ручной пункт чек-листа prod: в
  Supabase капча включена ⇔ в Vercel задан ключ сайта.
- 28.09.2026 первая регистрация на prod упала именно так: капча в Supabase
  была включена, виджета в приложении не было, а форма показывала «возможно,
  такой email уже занят» на любую ошибку. Разбор кодов Auth теперь в
  `authErrorMessage` (`apps/web/lib/errors.ts`).

## Дополнение 3.10.2026: код из письма вместо ссылки

**Проблема.** Ссылка из письма работает только в том браузере, где начали
регистрацию или вход (PKCE). Специалист открывает приглашение в WhatsApp, а
письмо — в приложении Gmail: ссылка открывается в другом браузере и «не
срабатывает». Это главная причина жалоб «сложно зарегистрироваться».

**Решение.** После регистрации и после «Войти по коду из письма» форма
переходит на шаг «Введите код из письма» (`components/email-code-step.tsx`).
Код проверяет `supabase.auth.verifyOtp({ email, token, type: 'email' })`
(`lib/email-code.ts`) — на той же странице, поэтому неважно, где открыто
письмо. Приглашение после кода принимается сразу. Ссылка в письме остаётся
запасным путём. Сброс пароля по-прежнему ссылкой.

**Шаблоны писем — в дашборде, не в репозитории** (Authentication → Emails →
Templates, на prod `vlsnfuhmozkywbovkazc`). Без `{{ .Token }}` в шаблоне код в
письмо не попадёт, и шаг «Введите код» оставит человека без кода — **шаблоны
меняются до выката кода на prod.** Текст для вставки:

*Confirm signup* — тема `Код подтверждения LogoCRM: {{ .Token }}`

```html
<h2>Подтвердите почту</h2>
<p>Ваш код для LogoCRM:</p>
<p style="font-size:28px;font-weight:bold;letter-spacing:6px">{{ .Token }}</p>
<p>Введите его на странице, где вы регистрировались. Код действует 1 час.</p>
<p>Открыли письмо в том же браузере, где регистрировались, — можно просто <a href="{{ .ConfirmationURL }}">нажать сюда</a>.</p>
<p>Вы не регистрировались в LogoCRM — просто удалите это письмо.</p>
```

*Magic link* — тема `Код для входа в LogoCRM: {{ .Token }}`

```html
<h2>Вход в LogoCRM</h2>
<p>Ваш код для входа:</p>
<p style="font-size:28px;font-weight:bold;letter-spacing:6px">{{ .Token }}</p>
<p>Введите его на странице входа. Код действует 1 час.</p>
<p>Открыли письмо в том же браузере, где входите, — можно просто <a href="{{ .ConfirmationURL }}">нажать сюда</a>.</p>
<p>Вы не запрашивали вход — просто удалите это письмо.</p>
```

Код в теме письма — намеренно: его видно в уведомлении на телефоне, письмо
можно не открывать. Длина кода — настройка проекта (по умолчанию 6), форма
принимает 6–10 цифр. На staging подтверждение почты выключено (см. выше), а
встроенная почта Supabase шлёт только участникам команды проекта — шаг с кодом
на staging проверяется только входом по коду на реальный адрес команды.
