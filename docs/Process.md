## Выкатка

Порядок, если в изменении есть миграция и бот:

1. PR → зелёный CI → владелец вливает кнопкой **Merge pull request** (не Squash и
   не Rebase: они меняют SHA, и на staging уедет непроверенный коммит).
2. Staging получает миграции сам.
3. Владелец запускает **Deploy production**.
4. Только после этого — бот: `railway up` из `apps/tg-bot` (CLI залинкован).
   Railway **не** выкатывает бота из GitHub сам; обычный Redeploy в панели
   пересобирает старый код. Если бот вызывает новую функцию раньше
   prod-миграции — команда падает.
5. После выкатки бота проверить меню: `getMyCommands`. При старте бот
   выставляет меню, но ответ Telegram не проверяет — 7.10 меню осталось
   старым, выставлено вручную.

Новые сценарии и ноды n8n владелец добавляет руками по `n8n/README.md`.

## CI и PR

- **CI запускается только при открытом PR.** Пуш в ветку без открытого PR не
  запускает ничего — ни ошибки, ни прогона. Закрытый PR = молчащие пуши.
- **CI сам пушит коммит с типами** (`chore(db): типы из схемы миграций`) в
  ветку PR с миграцией. После него: `git pull --ff-only`, иначе следующий пуш
  отклонят. Прогон этого коммита может ждать одобрения владельца.
- Новую RPC, которую сразу вызывает веб, до генерации типов CI можно вписать в
  `packages/db/src/database.types.ts` руками — CI перезапишет файл.
- **Пуш в ветку с открытым PR отменяет текущий прогон** — докоммичивать
  локально, пушить после зелёного.
- **`main` движется на масштабе минут.** Если CI падает на коде, которого нет в
  рабочей копии, — сначала `git log HEAD..origin/main`, потом гипотезы.
- **PR вливают быстро.** Открывать PR только с полным исправлением, не
  «открою и допушу»: второй коммит может не попасть в `main`. Проверять
  `git merge-base --is-ancestor`, а не «запушено».
- **Номер миграции** сверять прямо перед `gh pr create` и после каждого
  rebase: `git ls-tree origin/main packages/db/supabase/migrations/` и открытые
  PR. Дубль версии роняет `db reset` у всех (0015, 0021, 0025).
- **Одна сессия на репозиторий.** Две параллельные сессии конфликтуют в
  `docs/CHANGELOG.md` и `apps/web/messages/ru.json` при каждом мерже.
- Вливает в `main` только владелец; автоматический merge не включать.

## SQL

- **Ревью архитектора — два раза:** план до написания и написанный SQL до PR
  (или PR черновиком, пока замечания не закрыты). Только план + pgTAP
  пропускали блокеры: на этапе 4 — шесть, на 0041 открытый PR влили до ревью,
  и дыру чинила следующая миграция 0042.
- **Последнее определение функции или вью — только поиском по всем миграциям:**
  `grep -nE "create (or replace )?(function|view|procedure) public\.<имя>\b" migrations/*.sql`,
  брать самый поздний номер и сверять копию с ним. Тело из «помнящегося»
  файла уже дважды оказывалось устаревшим (`mark_attendance`, `student_balance`).
- **Гранты:** функции в `public` Supabase по умолчанию открывает `anon` и
  `authenticated` — RLS их не защищает. Каждая функция заканчивается явными
  `revoke` и `grant` (см. CLAUDE.md), заборы — `tests/0007`.
- **Архив — через RPC.** Прямой `update deleted_at` не проходит RLS: PostgREST
  добавляет `RETURNING`, а политика `using (deleted_at is null)` не видит
  строку после обновления. Паттерн — `archive_<таблица>`.
- **`deleted_at` у абонемента — архив** исчерпанного или отменённого, не
  «ошибочная запись»: триггер на архив не должен откатывать оплаченное (0088).
- **`student_balance.lessons_left = null`** значит и «безлимит», и «нет
  абонемента» (заморозка тоже даёт NULL) — различает `active_subscription_id`.
- **Время — параметром.** Планировщик, зависящий от часа, пишется как
  внутренняя `*_at(p_now)` без грантов; публичная функция — обёртка с `now()`.
  Иначе тест зависит от часа прогона CI (0097).

## pgTAP

- **`reset role` не сбрасывает claims.** `auth.uid()` остаётся от последнего
  `tests_claims`. После блока «чужой центр / специалист / родитель» — явный
  `tests_claims(<владелец>)`; вызов «от воркера» — `tests_claims(null, null)`.
  Иначе голый вызов падает вне `throws_ok`, файл обрывается одной строкой
  `ERROR` (было четыре раза).
- **Даты в тестах — далёкое будущее (2037+, тот же календарь, что 2026) или от
  `now()`.** Триггер состава группы и окна напоминаний работают только с
  будущими занятиями: зашитые «2026-10-08» 10.10.2026 стали прошлым, и
  tests/0006 упал на чужом PR.
- Временная таблица теста, которую читает `authenticated`, — с `grant select`.
- Менять срок центра в тесте можно только с отключённым `centers_protect_plan`
  или от имени администратора платформы.

## E2E (Playwright)

- **Локаторы сверять с текущим JSX до пуша**, не с заметками: `getByText` без
  `exact` находит и `<option>`, и тост — strict mode violation.
- **Фикстуру времени** (`fixtures/e2e.sql`) якорить на фиксированную дату, не на
  `now()`, и перед пушем искать всех потребителей по всем spec-файлам — фикс
  таймингов однажды занял три круга CI.
- **Форма, которая прячется при успехе** (например, `FreezeForm`), ломает
  `actAndAwait`: ждать результат напрямую, а не уведомление внутри формы.
- При падении — артефакт `playwright-report` из прогона (`gh run download`).

## Фронтенд

- **`loading.tsx` над `/app` запрещён:** Suspense превращает `redirect()` в 200
  с клиентским переходом и подвешивает действия с `revalidatePath` (PR #221).
  Отклик на клик — `LinkPending` (`useLinkStatus`).
- Не запускать `pnpm build`, пока работает `pnpm dev` (общий `.next`) — держит
  хук `no-build-while-dev.mjs`.

## Работа с браузером и процессами (для ИИ-помощника)

- В Browser pane кликать по `ref` из `find`/`read_page`, а не по координатам
  со скриншота: скриншот бывает отмасштабирован.
- Зависший headless Chrome убивать только по PID или узкому фильтру, никогда
  `pkill -f "Google Chrome"`: это закрывает браузер владельца.
