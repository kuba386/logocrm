# Матрица прав

Кто что видит и может. Источник — код: RLS-политики миграций и гейты в
`security definer`-функциях, а не замысел.

Пополняется по этапам — см. Definition of Done в
[Roadmap/stages.md](Roadmap/stages.md). Почему правило именно такое — в
[BUSINESS_RULES.md](BUSINESS_RULES.md).

## Как читать

| Знак | Значение |
|---|---|
| **В** | видит |
| **С** | создаёт |
| **П** | правит |
| **У** | удаляет — в этом проекте почти всегда «архивирует» (`deleted_at`). Настоящий `delete` есть ровно в одном месте: отзыв членства |
| **—** | нет доступа: не «кнопки нет», а база не отдаёт строк |

**`registrar` и `finance` — в схеме с 0026–0028.** Гейты RPC — три
предиката (`can_front_desk` = owner/admin/registrar, `can_finance` =
owner/admin/finance, `can_payments` = все четыре; `0026`), политики таблиц —
`tenant_registrar_*` / `tenant_finance_*` по явному списку (`0028`),
`tenant_admin` остаётся у owner/admin. Таблица без вызова `apply_role_rls`
закрыта для новой роли — pgTAP 0031 (забор переехал из 0028) держит полный
список политик по `pg_policies`. DELETE не выдаётся никому (`0024`).

`registrar` — стойка: ученики, плательщики, расписание, посещения,
абонементы, платежи и рассрочки. Не видит расходов, ставок и зарплат.
`finance` — бухгалтер: платежи, расходы, ставки, зарплаты, периоды, отчёты.
Не создаёт занятий и учеников, не гасит абонементы (возврат — стойка). Не
читает свободного текста о семье и занятии (`0031`, сноска ⁵).

Разница между `owner` и `admin` мельче, чем кажется: она есть только в
настройках центра, в управлении персоналом и в `reopen_month`. Во всём
остальном — одно и то же право.
